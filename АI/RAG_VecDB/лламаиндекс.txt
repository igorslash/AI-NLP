📋 Пошаговая памятка: инструменты LlamaIndex
1. Ingest (Загрузка данных)
Задача: Загрузить данные из файлов, веб-страниц, баз данных или SaaS-сервисов.

Основные инструменты:

SimpleDirectoryReader — самый простой способ загрузить папку с файлами.

LlamaParse — инструмент для «умного» парсинга сложных PDF-файлов (таблицы, диаграммы).

Специализированные Reader'ы из LlamaHub (например, для Notion, Slack, Google Drive).

Ключевая настройка: Нормализация метаданных (автор, дата, источник) для последующего фильтрования .

2. Chunk (Чанкинг / Разбиение)
Задача: Разбить большие документы на смысловые фрагменты (Nodes).

Основные инструменты:

SentenceSplitter — стандартный сплиттер с настройкой chunk_size и chunk_overlap.

SemanticSplitterNodeParser — семантический сплиттер для прозы.

HierarchicalNodeParser — для вложенных документов.

MarkdownNodeParser — для Markdown-файлов.

Ключевая настройка: Выбор размера чанка (например, 512–1024 токена) и перекрытия (10-20%) в зависимости от типа контента .

3. Index (Индексация)
Задача: Создать структуру данных, по которой можно эффективно искать.

Основные инструменты:

VectorStoreIndex.from_documents() — стандартный векторный индекс.

PropertyGraphIndex — для построения графа знаний и логических связей.

SummaryIndex — для создания сводок.

Ключевая настройка: Выбор векторного хранилища для продакшена (Pinecone, Qdrant, Weaviate, pgvector) вместо SimpleVectorStore .

4. Retrieve (Поиск / Извлечение)
Задача: Найти наиболее релевантные чанки в ответ на запрос.

Основные инструменты:

index.as_retriever() — базовый ретривер.

BM25Retriever — поиск по ключевым словам.

MergerRetriever — для гибридного поиска (вектор + ключевые слова).

Ключевая настройка: Гибридный поиск (векторный + BM25) является минимальной конфигурацией для продакшена .

5. Post-process (Постобработка / Реранкинг)
Задача: Переупорядочить найденные чанки, чтобы наверх попали самые релевантные.

Основные инструменты:

CohereRerank, FlagEmbeddingReranker, ColbertReranker.

MetadataReplacementNodePostProcessor — для подмены чанка на его «контекстное окно».

Ключевая настройка: Обязательно использовать реранкер, если вы используете гибридный поиск .

6. Synthesize (Синтез ответа)
Задача: Передать запрос и отобранный контекст в LLM для генерации ответа.

Основные инструменты:

index.as_query_engine() — основной интерфейс для запросов.

get_response_synthesizer() — для настройки стратегии (compact, tree_summarize, refine).

Ключевая настройка: Выбор response_mode в зависимости от размера контекста и стоимости токенов .

7. Agent / Workflow (Агенты и Рабочие процессы)
Задача: Создать многошаговые системы, где LLM может выбирать инструменты или выполнять действия.

Основные инструменты:

FunctionAgent, AgentWorkflow — для создания агентов с инструментами.

Workflow (с декораторами @step) — для событийно-ориентированной оркестрации.

QueryEngineTool — чтобы обернуть поисковый движок как инструмент для агента.

Ключевая настройка: Агенты в LlamaIndex — это предварительно настроенные Workflows. Для сложной логики используйте сырой Workflow .

8. Evaluate (Оценка)
Задача: Измерить качество поиска и ответов.

Основные инструменты:

FaithfulnessEvaluator — проверка на соответствие контексту.

RelevancyEvaluator — проверка на релевантность ответа.

ContextRelevance — оценка качества извлеченных чанков.

Ключевая настройка: Оценивать не только финальный ответ, но и качество поиска (retrieval) .

9. Deploy (Деплой)
Задача: Запустить систему в продакшене.

Основные инструменты:

llama-deploy — встроенный рантайм для развертывания.

Инструменты наблюдаемости (OpenTelemetry, LangSmith, FutureAGI).

Ключевая настройка: Обязательно настраивать трейсинг, чтобы видеть, какие чанки были извлечены и как они повлияли на ответ .
